Getting clean, correctly ordered text out of a PDF

A PDF does not store paragraphs the way a word processor does. It stores a long list of tiny text runs, each with its own position on the page, and nothing that says "this run belongs to that line" or "a new paragraph starts here". Pulling readable text back out means reconstructing that structure from the coordinates alone. Knowing how this tool does that explains both what it gets right and where it can slip.

How lines and paragraphs are rebuilt

Every text run reported by pdf.js carries a transform that places it on the page. The tool first converts those positions through the page's viewport transform, which bakes in any rotation, so a page turned ninety degrees is read in its visual order rather than its raw storage order. Runs are then grouped into lines by their baseline height: anything within roughly six tenths of the median glyph height counts as the same line. Within a line the runs are sorted left to right, and a space is inserted only where there is a genuine gap between the end of one run and the start of the next, which stops words being jammed together or split apart. A new paragraph is started when the vertical jump between two lines is clearly larger than the normal line spacing measured across the whole page.

Choosing a layout mode

Three layout modes cover the common needs. Paragraphs and line breaks is the default and suits ordinary prose. Line breaks only keeps every physical line, which is what you want for code, addresses, poetry or anything where the wrapping matters. Flow into one paragraph per page strips the internal line breaks and joins everything into running text, useful when you are going to re-wrap the text somewhere else. The "Rejoin hyphen-split words" option removes the hyphen and the break when a word was split across two lines, so "inter-" and "national" become one word again.

When a page has no text, and other scripts

If a page returns no characters at all, it almost always means the page is an image — a scan or a photo of paper — with no text layer to read. The tool collects those page numbers and shows them with a link to the OCR tool, which recognises text from the image itself. The per-page character counts are the quickest way to see at a glance which pages are real text and which are pictures. Because PDFs store text as Unicode, non-Latin scripts such as Devanagari, Tamil or Bengali extract cleanly when the document's fonts carry proper Unicode mapping; a file built from outline fonts or images will not, and OCR is the fallback there too.

Ranges, large files and encrypted PDFs

A page range such as 1-3, 5, 8-10 limits extraction to the pages you name, and blank means the whole document. Large files are read one page at a time with a progress bar, and Cancel stops the job while keeping whatever has been read so far. If the PDF is password-protected, the tool prompts for the password and will not proceed without it. The extracted text lands in an editable box, so you can tidy it before copying it or downloading a .txt file.
