Controlling Page Selection and Order When Combining PDFs

Order on screen is order in the output

The merge happens strictly in the sequence the cards appear, top to bottom. There is no hidden sort — whatever arrangement you see is exactly what the final file will contain. You can set that arrangement three ways: drag a card, use its up/down arrows, or pick an Output-order preset (Keep current, Reverse, or sort by filename A→Z or Z→A). The presets physically reorder the underlying list rather than just relabelling it, so applying "Reverse" and then merging genuinely flips the document order. This matters for the classic use case of resume followed by certificates: get the cards in the right order first, because the tool will not second-guess you.

Taking only some pages from a file

Each card has a page-range box. Leaving it blank includes every page; typing something like 1-3,5 takes only those pages from that specific file.In a range, pages past the end of the file are dropped rather than rejected: 1-999 on a ten-page file uses pages 1 to 10, and the hint under the box turns amber to say the range exceeds the page count and how many valid pages were kept. As you type, a live hint tells you what will happen: it confirms the valid page count, warns when a number exceeds the file's total (and notes that only the valid pages will be used), or flags genuinely malformed input like a reversed or non-numeric range. The running total at the bottom reflects your ranges, so you can see the merged page count before committing.

How problem files are handled

Adding files is forgiving. Non-PDF files are rejected by name, and a PDF that cannot be parsed — corrupt or password-protected — is skipped rather than aborting the whole batch, with a specific reason shown ("password protected" or "could not be read"). The readable files are still added and each shows a page-1 thumbnail generated by pdf.js, which is a quick way to confirm you grabbed the right document. A few things to know about scope:

  • There is no hard file-count limit, but you need at least two files before the Merge button activates.
  • A warning appears once the combined size passes 50 MB, because merging large sets in the browser can become slow or exhaust memory — this is a genuine constraint of doing the work client-side, not a soft nag.
  • Password-protected PDFs cannot be merged at all; remove the protection first with another tool, then add them here.

Verifying the result and your privacy

After merging, the result line states the final page count and file size, which is your first check — if the page count does not match the total you expected from your ranges, revisit the range hints. The "Copy merge order" button produces a plain-text manifest listing each file, its position, page count and any range, which is handy for confirming an order with a colleague before you generate the file. All processing uses pdf-lib for the merge and pdf.js for thumbnails, entirely in your browser; the PDFs never leave your device, and the only thing remembered between visits is your chosen output-order preset.
