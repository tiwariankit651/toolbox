How the minifier works, and what each option changes in your output

Two engines, loaded differently on purpose

CSS and JavaScript are minified by two different, well-established libraries, and the page treats them differently for a practical reason. CSS goes through csso 5.0.5, which is small enough to load alongside the page with no noticeable cost. JavaScript goes through terser 5.31.6, whose bundle is roughly a megabyte — large enough that loading it on every visit would slow the page for everyone, including the many people who only want to minify CSS. So terser is fetched lazily: the first time you click the JavaScript tab, the script is added with its Subresource Integrity hash and crossorigin set, and the status line tells you it is loading. Once fetched, the browser caches it, so subsequent minifications are instant. Both libraries run entirely in your browser; your code is never sent anywhere.

The CSS options

csso has two levels of work. The baseline always removes comments, redundant whitespace and other dead characters. The structure optimisation toggle controls the more aggressive pass that merges duplicate rules, combines adjacent blocks and reorders declarations where it is provably safe. That pass produces smaller output but changes the order of rules, which occasionally matters when two selectors of equal specificity set the same property. If you need the rule order preserved exactly, turn structure optimisation off and csso will only strip whitespace. Either way, the selectors and the declarations themselves are retained: color: #ffffff becomes color:#fff, and a @media block stays a @media block.

The JavaScript options

Four toggles and a target map onto terser's own settings. Compress enables terser's optimiser — dead-code removal, constant folding and so on. Mangle renames local identifiers to short names, which is where most of the byte saving in real code comes from. Keep function names protects function names from mangling, important when code inspects fn.name or relies on named stack frames. Drop console.* removes console calls as part of compression, a clean way to strip debugging output from a build. The ECMAScript target tells terser which syntax it may emit, so you do not accidentally ship newer syntax than your runtime supports. The combination you choose is saved in your browser for next time.

Sizes, the gzip estimate, beautify and errors

After every run the tool reports the original size, the output size and the percentage saved. Raw bytes, though, are not what a server actually transmits — assets are normally gzip-compressed in transit — so when your browser supports the CompressionStream API the tool gzips the output in memory and shows that figure too; on browsers without it the gzip line is simply omitted rather than invented. Beautify reverses the process: terser prints JavaScript with indentation and comments intact, and a brace-aware pretty-printer re-indents CSS while skipping over strings and comments so it never corrupts a value. When input has a syntax error, csso or terser reports it and the message is shown with its line and column.
