Frequently Asked Questions

What are the URL-safe and padding checkboxes for?

URL-safe Base64 swaps + and / for - and _ so the string is safe in URLs and filenames. The padding checkbox controls whether trailing = characters are kept. Encoding is UTF-8 aware (via TextEncoder), so accented characters and emoji round-trip correctly rather than corrupting, which plain btoa would do. When decoding, it auto-fixes missing padding and detects URL-safe input.

Can I turn a file into Base64, and get a ready-to-use CSS snippet?

Yes. Drop one or more files on the File tab. For an image you get a size readout with the percentage overhead, a live preview, and a copy-ready background-image: url("data:...") CSS snippet. You can output either raw Base64 or the full data URI including the MIME type. Files over about 8MB trigger a slow-encoding warning.

How does Base64 → File detect the file type?

Paste a data URI and it reads the MIME type directly; paste raw Base64 and it inspects the first bytes (magic numbers) to identify PNG, JPEG, GIF, PDF, ZIP, WAV, MP3, BMP or XML, falling back to octet-stream. It then downloads with a matching extension, or a filename you supply. Images are also previewed before download.

What do the Hex and URL tabs add?

The Hex tab converts text to space-separated hex bytes and back (UTF-8), rejecting odd-length or non-hex input. The URL tab offers Encode (encodeURI), Encode Component (encodeURIComponent) and Decode, treating + as a space on decode. Your text draft, chosen options and active tab are autosaved in your browser and restored on reload; a Clear draft button removes them.

Encoding Text and Files Without Corruption: UTF-8, URL-Safe and Type Detection

Why this avoids the classic btoa bug

The common way to make Base64 in a browser, btoa, throws or corrupts when given anything outside Latin-1 — accented letters, Devanagari, emoji. This tool encodes through TextEncoder first, converting your text to UTF-8 bytes before Base64, so a string with é, ₹ or 😀 round-trips back to exactly what you typed. Decoding uses a strict UTF-8 decoder, which means genuinely invalid input fails loudly with an error rather than returning silent garbage.

Base64 inherently grows data by about a third because it represents three bytes as four characters. The tool shows this directly as a percentage overhead after encoding, so the larger output size is expected, not a malfunction.

URL-safe and padding, and when you need them

Standard Base64 uses + and /, which are unsafe in URLs and filenames. The URL-safe checkbox swaps them for - and _. The padding checkbox controls the trailing = characters. These only matter for interoperability: if a system gave you a token with - and _ and no =, decode it with URL-safe on. Helpfully, the decoder is forgiving in one direction — it detects URL-safe characters automatically and re-adds missing padding before decoding, so a stripped token usually decodes even if you forget to tick the box.

Turning files into data URIs the right way

On the File tab you can output either raw Base64 or a full data URI that includes the MIME type (the data:image/png;base64,… form). For images the tool also builds a ready-to-paste background-image: url("data:…") CSS snippet and shows a live preview, so you can confirm the embed renders before copying. A size readout reports the original versus Base64 size with the overhead percentage. Files beyond roughly 8MB trigger a slow-encoding warning because the work happens on the main thread in your browser; very large embeds also bloat the HTML or CSS they land in, which is a reason to prefer a linked file over a data URI for big assets.

Decoding back to a file, and the other tabs

Base64 → File detects the type one of two ways. If you paste a full data URI it trusts the declared MIME type. If you paste raw Base64 it decodes the bytes and inspects the first few (the "magic numbers") to recognise PNG, JPEG, GIF, PDF, ZIP, WAV, MP3, BMP or XML, defaulting to a generic binary type when nothing matches. It then downloads with a sensible extension, or a filename you supply.

  • The Hex tab converts text to space-separated hex bytes and back as UTF-8, rejecting odd-length or non-hex input.
  • The URL tab distinguishes encodeURI (whole URLs) from encodeURIComponent (single values), and treats + as a space when decoding.
