The three URL parameters, which are not interchangeable

Linking to a moment in a video uses a different parameter depending on the URL form, and using the wrong one silently does nothing.

  • Watch URL: &t=90, or ?t=90 if there is no other parameter.
  • Short youtu.be URL: ?t=90, always with a question mark.
  • Embed URL: ?start=90 — a different name entirely. Using t= on an embed has no effect, which is the most common confusion here. An embed also accepts &end=120, which the watch URL does not.

The value accepts 90, 90s or 1m30s. Plain seconds is safest because every context accepts it.

Five conditions for chapters to appear

Chapters are generated from timestamps in the description and appear only if all of these hold. Missing any one produces clickable times and no chapter bar.

  1. The first timestamp must be 0:00. Starting at 0:15 produces no chapters at all — the single commonest cause.
  2. At least three timestamps. Two is not enough.
  3. Each chapter at least ten seconds long.
  4. Ascending order.
  5. One per line, timestamp first, title after.

Why timestamps drift after an edit

Trim four seconds from the opening and re-export, and every chapter after that point is four seconds early — each one now begins just before its topic, showing the tail of the previous section.

Two ways to handle it. Apply the offset to every timestamp uniformly, which is mechanical and reliable. Or build the chapter list only after the edit is final — obvious in hindsight and routinely not done, because you note the times while reviewing.

Writing titles that work as a contents page

Keep them around forty characters, since they are truncated in the chapter bar, and start with the distinguishing word rather than a repeated prefix. Six chapters all beginning "How to" are harder to scan than six beginning with the thing itself.

For a video under about five minutes chapters add little. Above ten minutes they change how it is used — people arrive from search, jump to the relevant part, and stay.
