Frequently Asked Questions

Which formats can it convert between?

It converts to JPEG, PNG, WebP, AVIF and BMP, and reads any image your browser can display. On load it tests whether your browser can actually encode WebP and AVIF and shows a warning if the chosen format isn't supported, so you won't get a silent empty file.

What happens to transparency when I convert a PNG to JPEG?

JPEG and BMP can't store transparency, so when you pick one of those a 'Background for transparency' colour picker appears (default white). Transparent pixels are composited onto that colour before encoding, which prevents the common black-box-around-the-logo surprise. For PNG, WebP and AVIF output, transparency is preserved.

Can I resize or hit a target file size during conversion?

Yes. Resize mode offers 'Max width/height' (scales down to fit, preserving ratio) or 'Scale %'. For lossy formats (JPEG/WebP/AVIF) you can set a Target size in KB, which the tool meets with an ~8-iteration binary search on quality; otherwise you control the quality slider directly (default 92%).

Does converting remove EXIF metadata like GPS?

Yes — because conversion re-encodes through a canvas, EXIF metadata is stripped by default, so location and camera data don't carry into the output. The tool's own notes caution that format conversion alone isn't a reliable way to strip metadata in general, but this canvas-based converter does drop it. You can batch-convert and download all as a ZIP.

Which format to use, and why

The choice is decided by what the image contains, not by preference.

FormatUse forAvoid for
JPEGPhotographsText, line art, anything needing transparency
PNGScreenshots, logos, text, transparencyLarge photographs — files get very big
WebPWeb use, where it is 25-35% smallerAnywhere a recipient may not support it
SVGLogos and icons, at any sizePhotographs — it is not a photo format

The reason behind the table: JPEG compression is designed around how the eye perceives photographs, so it discards detail you are unlikely to notice in a continuous-tone image. On the hard edges of text that same compression produces visible fringing, which is why a screenshot saved as JPEG looks dirty around the letters.

Lossy and lossless, and why quality degrades

PNG is lossless — decoding returns exactly the pixels that were encoded, and re-saving it costs nothing.

JPEG is lossy, and each save discards information permanently. Converting JPEG to PNG does not recover what was lost; it preserves the already-degraded pixels in a lossless container. The damage happened at the first JPEG save.

This is why opening a JPEG, making a small edit and saving repeatedly produces an image that visibly deteriorates — generation loss. The habit that avoids it: keep the original, edit from it each time, and export rather than re-save.

Transparency, which is where conversions go wrong

JPEG has no alpha channel. Converting a transparent PNG to JPEG must fill the transparent area with something, and the common default is black.

This is the single most frequent surprise in format conversion: a logo that looked fine on a white page arrives with a black box around it. Where the destination needs JPEG, composite the image onto white deliberately before converting rather than letting the encoder decide.

What converting does not remove

A JPEG from a phone carries EXIF metadata — the camera, the settings, the date, and frequently GPS coordinates. Converting the format does not reliably strip it, and some converters carry it across.

If an image is going anywhere public, the location data is the part worth caring about. Stripping metadata is a separate operation from converting, and worth doing explicitly.

One more thing conversion does not remove: anything visible in the image. Blurring or pixelating a region in a tool that writes a new file does remove it; drawing a black box in a format that keeps layers may not.
