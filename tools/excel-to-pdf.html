📊 Excel to PDF

Turn an Excel workbook or CSV into a clean, printable PDF — pick which sheets, the page size and orientation, whether columns should fit the page width, and whether the header row repeats on every page. The file is read in this tab with SheetJS and the PDF is built here with pdf-lib, so your spreadsheet is never uploaded.

How to Use This Tool

  1. Drop your spreadsheet — an .xlsx, .xlsm, older .xls or a .csv. Every sheet in the workbook is listed with a checkbox so you choose exactly which ones go into the PDF.
  2. Pick the page size and orientation. Leave orientation on "Auto" and the tool switches a wide sheet to landscape by itself; force portrait or landscape if you prefer.
  3. Decide what happens to wide sheets. "Fit to width" shrinks the columns so they all sit on one page across; "Split columns across pages" keeps the font size and continues the extra columns on following pages, repeating the first (label) column.
  4. Turn on repeating headers and page numbers so a long register stays readable — the header row is reprinted at the top of every page and "Page x of y" is stamped at the foot.
  5. Check the first-page preview, then Download PDF. One sheet saves as <file>-<sheet>.pdf; several sheets save as <file>.pdf.

Common Use Cases

  • Marksheet, attendance register or fee register kept in Excel that has to be submitted or printed as PDF
  • A GST or sales report with ₹ amounts that must look exactly as it does in Excel — the rupee sign prints correctly here
  • A wide stock or inventory sheet with 20+ columns that needs to fit one page across
  • A Hindi or regional-language sheet (names, addresses) that other converters turn into boxes
  • A multi-sheet workbook where each sheet should start on its own page in a single PDF
  • A CSV export from a bank or portal that you want as a tidy, paginated PDF

About This Tool

Convert Excel and CSV files to PDF without installing software or uploading anything. The workbook is parsed in your browser by SheetJS — using each cell's formatted text, so numbers, dates, percentages and currency appear just as they do in Excel — and the PDF is assembled locally with pdf-lib. Each sheet is drawn to a high-resolution canvas and embedded as a crisp image page, which is why Devanagari text and the ₹ symbol print correctly instead of coming out as question marks or empty boxes. Merged title cells (!merges), column widths (!cols) and row heights are honoured where the workbook stores them, numbers are right-aligned, and the header row can be bolded and repeated on every page.

Frequently Asked Questions

Will the ₹ rupee sign and Hindi text print correctly in the PDF?

Yes. Instead of embedding a limited PDF font that only covers Latin letters, each sheet is drawn onto a high-resolution canvas using the fonts your browser already has, and that canvas is embedded into the PDF. So any Unicode text the browser can display — the ₹ symbol, Devanagari, Tamil, Marathi — prints exactly as it looks, rather than turning into boxes or question marks.

My sheet has 25 columns and they run off the page. What can I do?

Two options under 'When columns don't fit'. 'Fit to width' scales every column down proportionally so they all sit across one page (combine with landscape for very wide sheets). 'Split columns across pages' keeps the font size and continues the extra columns on following pages, repeating the first column as a label so you can still tell which row is which.

Does it keep merged title cells, column widths and show numbers the way Excel does?

Yes. Merged ranges from the workbook's !merges are drawn as a single spanning cell, column widths from !cols (wpx or wch) and row heights from !rows are honoured when present, numeric cells are right-aligned by default, and the header row can be bolded. Crucially it uses each cell's formatted text (SheetJS .w), so a date, percentage or currency value reads the same as it does in Excel rather than as a raw number.

Can I convert only some sheets, and how is the file named?

Every sheet in the workbook is listed with a checkbox, so you convert exactly the ones you tick and each starts fresh in the combined PDF. If you convert a single sheet the file is saved as <file>-<sheet>.pdf; if you convert several it is saved as <file>.pdf. Empty sheets are skipped and reported.

From Spreadsheet to Print-Ready PDF: Fitting, Headers and Why ₹ Prints Correctly

Formatted values, not raw numbers

When the workbook is read, the tool deliberately asks SheetJS for each cell's formatted text rather than its underlying number. A date stored as the serial 45658 is pulled out as "01/01/2025", a percentage shows as "12%" and a currency cell shows as "₹1,250.00" — exactly the string Excel paints on screen. This matters because a PDF is a frozen picture of your data: if it showed 45658 where you expected a date, the document would be useless. The one place raw type is still consulted is alignment — cells Excel treats as numeric are right-aligned by default, matching spreadsheet convention, while text stays left-aligned. You can turn that behaviour off if a column of ID numbers reads better on the left.

Deciding orientation and making wide sheets fit

A spreadsheet has no natural page, so the tool has to invent one. First it measures every column — using the workbook's stored widths (!cols) when they exist, otherwise the widest piece of text in the column, capped so one enormous cell can't push everything off-screen. It adds those widths up. On "Auto" orientation, if the total is wider than the usable page it switches to landscape by itself; you can also force portrait or landscape. If the columns still overflow, two strategies are offered. Fit to width multiplies every column by a single scale factor so they collapse onto one page across — ideal for a 25-column inventory sheet you want on a single landscape page. Split columns across pages keeps the font readable and instead carries the extra columns onto following pages, reprinting the first column as a row label so you never lose track of which line is which.

Repeating headers, page numbers and merged cells

Long registers are only usable if you can read them away from page one. Tick "Repeat header row on every page" and the first row is redrawn at the top of each page, bolded if you like, with a light shaded background. "Page x of y" is stamped at the foot so a printed stack stays in order, and the sheet name can sit as a heading above the table. Merged title cells from !merges are drawn as a single wide cell spanning their columns, and the cells hidden underneath the merge are skipped so text is never printed twice. Row heights from !rows are respected where the file stores them. For long cell text you choose between wrapping inside the column — the row grows taller to fit — or clipping with an ellipsis when you prefer every row the same height.

Why the PDF is built from canvas pages

The hardest part of any spreadsheet-to-PDF tool is text that isn't plain English. The standard PDF fonts only cover the WinAnsi character set, which has no ₹ and no Devanagari, so a naive converter prints boxes or question marks — a real problem for Indian sheets where the rupee sign is everywhere. This tool sidesteps that entirely: each page is drawn on a high-resolution canvas using the fonts your own browser has, then embedded into the PDF with pdf-lib as a crisp image. Whatever your browser can display — ₹, Hindi, Tamil, emoji — appears in the PDF. The trade-off is that the PDF stores pictures of pages rather than selectable text, so you can't copy text out of it; in exchange you get a document that looks right in every language and prints identically everywhere. Everything happens in your browser, so a salary sheet or student register is never uploaded.
