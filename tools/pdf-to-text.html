Frequently Asked Questions

Why does a page come out blank or get flagged as scanned?

This tool reads the text layer a PDF already contains; it does not do OCR. A page that is just a photo or scan of paper has no text layer, so nothing can be extracted from it. When a selected page returns no characters, the tool lists it by number and shows a link to the OCR tool at /tools/ocr, which reads text from the image instead. The per-page character counts make it easy to spot which pages are text and which are images.

How are paragraphs and line breaks decided?

Characters are grouped into lines by their vertical position on the page, and each line is read left to right, with a space inserted wherever there is a real gap between words. In the default Paragraphs mode a blank line is added when the vertical gap between two lines is clearly larger than the normal line spacing, which is how a new paragraph usually looks. You can instead choose Line breaks only to keep every line, or flow each page into a single paragraph. Rotated pages are normalised first so they read in the right order.

Can it read Hindi, Devanagari or other non-English text?

Yes, as long as the PDF stores that text as real characters with proper Unicode mapping in its fonts. PDFs keep text as Unicode, so Devanagari, Tamil, Bengali and other scripts come through unchanged. If a document was built from images of text, or uses fonts with no Unicode mapping, the characters may come out garbled or empty — that is a property of the file, and OCR is the fallback for it.

How do page ranges, page separators and large files work?

Type a range such as 1-3, 5, 8-10 to pull only those pages; leave it blank for the whole document. The Page separators option inserts a labelled divider before each page's text. Large PDFs are processed one page at a time with a progress bar, and a Cancel button stops the job and keeps whatever was already read. You can also rejoin words split by a hyphen at the end of a line. The result sits in an editable box you can copy or download as a .txt file.

How to Use This Tool

  1. Step 1: Drop a PDF that has a real text layer (a document exported from Word, a web page or an e-book reader, not a photo).
  2. Step 2: Pick how you want the text shaped — paragraphs and line breaks, line breaks only, or everything flowed into one paragraph per page.
  3. Step 3: Optionally type a page range like 1-3, 5, and decide whether to keep page separators.
  4. Step 4: Click Extract Text. A progress bar shows each page, and you can cancel a long document at any time.
  5. Step 5: Read the per-page character counts, then copy the text or download it as a .txt file.

Common Use Cases

  • Copying quotes and references out of a research paper or e-book.
  • Getting the body text of a contract or report into a word processor.
  • Feeding a document's text into a summariser, translator or grammar checker.
  • Checking which pages of a scanned file actually carry a text layer.
  • Pulling data out of a form-filled PDF without retyping it.

Getting clean, correctly ordered text out of a PDF

A PDF does not store paragraphs the way a word processor does. It stores a long list of tiny text runs, each with its own position on the page, and nothing that says "this run belongs to that line" or "a new paragraph starts here". Pulling readable text back out means reconstructing that structure from the coordinates alone. Knowing how this tool does that explains both what it gets right and where it can slip.

How lines and paragraphs are rebuilt

Every text run reported by pdf.js carries a transform that places it on the page. The tool first converts those positions through the page's viewport transform, which bakes in any rotation, so a page turned ninety degrees is read in its visual order rather than its raw storage order. Runs are then grouped into lines by their baseline height: anything within roughly six tenths of the median glyph height counts as the same line. Within a line the runs are sorted left to right, and a space is inserted only where there is a genuine gap between the end of one run and the start of the next, which stops words being jammed together or split apart. A new paragraph is started when the vertical jump between two lines is clearly larger than the normal line spacing measured across the whole page.

Choosing a layout mode

Three layout modes cover the common needs. Paragraphs and line breaks is the default and suits ordinary prose. Line breaks only keeps every physical line, which is what you want for code, addresses, poetry or anything where the wrapping matters. Flow into one paragraph per page strips the internal line breaks and joins everything into running text, useful when you are going to re-wrap the text somewhere else. The "Rejoin hyphen-split words" option removes the hyphen and the break when a word was split across two lines, so "inter-" and "national" become one word again.

When a page has no text, and other scripts

If a page returns no characters at all, it almost always means the page is an image — a scan or a photo of paper — with no text layer to read. The tool collects those page numbers and shows them with a link to the OCR tool, which recognises text from the image itself. The per-page character counts are the quickest way to see at a glance which pages are real text and which are pictures. Because PDFs store text as Unicode, non-Latin scripts such as Devanagari, Tamil or Bengali extract cleanly when the document's fonts carry proper Unicode mapping; a file built from outline fonts or images will not, and OCR is the fallback there too.

Ranges, large files and encrypted PDFs

A page range such as 1-3, 5, 8-10 limits extraction to the pages you name, and blank means the whole document. Large files are read one page at a time with a progress bar, and Cancel stops the job while keeping whatever has been read so far. If the PDF is password-protected, the tool prompts for the password and will not proceed without it. The extracted text lands in an editable box, so you can tidy it before copying it or downloading a .txt file.

About This Tool

PDF to Text reads the text layer that most PDFs already contain and reconstructs it in reading order. It groups characters into lines by their vertical position, sorts each line left to right, inserts spaces where there are gaps between words, and starts a new paragraph when the vertical gap between lines is noticeably larger than the line spacing. Rotated pages are handled, and a page with no recoverable text is flagged as likely scanned, with a link to the OCR tool for those pages. Because PDFs store Unicode, non-Latin scripts such as Devanagari come through when the PDF's fonts carry that mapping. All of the work happens inside your browser with pdf.js — the PDF is never sent anywhere.
