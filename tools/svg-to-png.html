How to Use This Tool

  1. Add your SVGs. Drop in one or several .svg files, or paste SVG markup into the box and press "Add pasted SVG". Each one shows up as a card.
  2. Pick the output format. PNG and WebP keep transparency; JPG cannot, so choosing JPG reveals a background colour picker (white by default) that fills the see-through areas.
  3. Choose the size. A plain SVG has no fixed pixels, so pick 1×–4× of its natural size (read from width/height or the viewBox) or type an exact width — the height follows the aspect ratio automatically.
  4. Read the preview over a checkerboard, which shows exactly which pixels are transparent before you save.
  5. Download each card, or ZIP them all when you have converted several at once.

About This Tool

Convert SVG vector graphics to PNG, JPG or WebP without uploading them anywhere. Each SVG is loaded into an <Image> from a Blob URL and drawn onto a canvas, which is then encoded in the format you choose — the file never leaves your device. This <img> route is also a deliberate security choice: SVG is XML and can contain <script> or event handlers, but scripts inside an image loaded this way do not execute and the markup is never inserted into the page, so a hostile SVG cannot run code in your browser. The tool reads intrinsic size from the SVG's width/height or falls back to its viewBox, handles files that specify neither, and understands unit suffixes such as pt and mm. PNG and WebP preserve transparency; JPG composites onto a background colour you choose; and the output is capped at 8192 px per side.

Rasterising Vectors Safely: Intrinsic Size, Transparency and the <img> Security Boundary

Why an SVG is loaded as an image, never injected into the page

An SVG file is not really a picture — it is an XML document, and XML can carry <script> elements and event handlers like onload. If a tool were to drop SVG markup straight into the page with innerHTML, those scripts would run with full access to the page. This converter refuses to do that. Every SVG, whether dropped as a file or pasted as code, is wrapped in a Blob and loaded into an ordinary <img> element by its Blob URL. Browsers treat an image as inert: scripts and handlers inside an SVG loaded through <img src> simply do not execute, and the raw markup is never parsed into live DOM nodes. The practical upshot is that you can convert an SVG you downloaded from anywhere without worrying that opening it will run code, because to this tool it is only ever a flat picture to be drawn on a canvas.

Working out how big the image should be

Because vectors have no fixed pixel size, the tool has to decide the natural dimensions before it can rasterise. It reads the opening <svg> tag out of the text — again without building any live nodes — and looks for width and height attributes first. Those can carry units: pt, mm, cm, in and pc are all converted to pixels at 96 DPI. If an attribute is a percentage, or missing entirely, the tool falls back to the viewBox to recover the proportions, and only uses a default when neither width/height nor a viewBox is present. When just one of width or height is given alongside a viewBox, the other is derived so the aspect ratio stays true. A copy of the SVG then gets explicit width and height written onto it, which some browsers (Firefox in particular) need before they will give an <img> a definite intrinsic size.

Scaling, exact width and the memory guard

Once the natural size is known, the output can be set as a simple multiple — 1×, 2×, 3× or 4× — which is the quick way to get a sharp high-DPI PNG of an icon. Alternatively you type an exact target width and the height is computed from the aspect ratio automatically, so you never squash the graphic. Scaling up stays crisp because the browser re-renders the vector at the new resolution rather than enlarging pixels. To stop an accidental huge value from crashing the tab, the longest side is capped at 8192 px; if a request exceeds that, both dimensions are scaled back together so the proportions are preserved.

Transparency, JPG backgrounds and batch output

PNG and WebP keep the alpha channel, so a logo stays transparent. The preview sits on a light/dark checkerboard specifically so you can see which pixels are see-through before you commit — a solid-looking white area and a transparent area look identical until you put a pattern behind them. JPG cannot store transparency at all, so selecting it reveals a background colour picker (white by default); the transparent region is filled with that colour on the canvas before encoding, which prevents the usual black box appearing behind the artwork. For JPG and WebP a quality slider trades file size against fidelity. When you convert several SVGs at once each gets its own card with a download button, and a single "Download all as ZIP" button bundles every successful conversion, de-duplicating names so two files called logo.svg don't overwrite each other.
