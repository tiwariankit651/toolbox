Frequently Asked Questions

Why does JavaScript mode take a moment the first time?

The JavaScript side is powered by terser 5.31.6, whose bundle is around 1 MB. To keep the page fast, terser is not loaded with the page — it is fetched the first time you switch to the JavaScript tab (with Subresource Integrity and crossorigin set), and the browser caches it after that. CSS mode uses csso 5.0.5, which is small and loads with the page.

What do the JavaScript options actually do?

Compress removes dead code and shortens expressions; Mangle renames local variables to single letters; Keep function names stops mangling from renaming functions (useful when code relies on fn.name); Drop console.* strips console calls during compression; and the ECMAScript target tells terser which syntax level it may emit. The combination you pick is remembered in your browser for next time.

What is the gzip estimate and when does it appear?

Raw byte size is not what a server actually sends — assets are usually gzip-compressed in transit. When your browser supports the CompressionStream API, the tool gzips the output in memory and shows that size next to the raw output size, which is a far better guide to real transfer cost. On browsers without CompressionStream the gzip figure is simply omitted rather than guessed.

Can I minify a very large file?

Yes, files up to 100 MB are accepted (phones are asked to confirm above 25 MB). Files over 2 MB are kept in memory and processed in a background worker, so the page stays usable, with progress and a Cancel button; the boxes show only the first 200 KB, and Copy and Download use the full result. Expect CSS to be quick and JavaScript to be slow: in testing on a desktop, 9.5 MB of CSS minified in about 7 seconds and beautified in about 1.4 seconds, while 9.5 MB of JavaScript took about 8 seconds to beautify but about 5 minutes to minify with compress and mangle on. Turning compress off is much faster.

How to Use This Tool

  1. Pick CSS or JavaScript: Use the tabs at the top — the options below change to match.
  2. Paste or drop your code: Add it to the input box or drop a .css or .js file onto the drop zone.
  3. Set the options: For CSS, toggle structure optimisation. For JS, choose compress, mangle, keep function names, drop console, and the ECMAScript target.
  4. Minify: Click Minify. The first time you use JS mode the terser library (about 1 MB) is fetched — after that it is cached.
  5. Check the numbers: The sizes line shows original, minified, gzip estimate (when your browser supports CompressionStream) and the percentage saved. Copy or download the result.

About This Tool

A two-in-one minifier and beautifier for CSS and JavaScript that runs entirely in your browser. CSS is processed by csso 5.0.5, with an optional structure optimisation pass that merges and reorders rules; disabling it keeps the original rule order and only strips whitespace. JavaScript is processed by terser 5.31.6, which is loaded on demand only when you first switch to JS mode because the bundle is around 1 MB. Terser options exposed here are compress, mangle, keep function names, drop console calls and the ECMAScript target. Beautify mode re-expands either language — terser with beautify output for JS, and a safe brace-and-declaration pretty-printer for CSS. The tool reports input size, output size, a gzip estimate using the browser's CompressionStream when available, and the percentage saved. Parse errors from either library are shown with their line and column.

How the minifier works, and what each option changes in your output

Two engines, loaded differently on purpose

CSS and JavaScript are minified by two different, well-established libraries, and the page treats them differently for a practical reason. CSS goes through csso 5.0.5, which is small enough to load alongside the page with no noticeable cost. JavaScript goes through terser 5.31.6, whose bundle is roughly a megabyte — large enough that loading it on every visit would slow the page for everyone, including the many people who only want to minify CSS. So terser is fetched lazily: the first time you click the JavaScript tab, the script is added with its Subresource Integrity hash and crossorigin set, and the status line tells you it is loading. Once fetched, the browser caches it, so subsequent minifications are instant. Both libraries run entirely in your browser; your code is never sent anywhere.

The CSS options

csso has two levels of work. The baseline always removes comments, redundant whitespace and other dead characters. The structure optimisation toggle controls the more aggressive pass that merges duplicate rules, combines adjacent blocks and reorders declarations where it is provably safe. That pass produces smaller output but changes the order of rules, which occasionally matters when two selectors of equal specificity set the same property. If you need the rule order preserved exactly, turn structure optimisation off and csso will only strip whitespace. Either way, the selectors and the declarations themselves are retained: color: #ffffff becomes color:#fff, and a @media block stays a @media block.

The JavaScript options

Four toggles and a target map onto terser's own settings. Compress enables terser's optimiser — dead-code removal, constant folding and so on. Mangle renames local identifiers to short names, which is where most of the byte saving in real code comes from. Keep function names protects function names from mangling, important when code inspects fn.name or relies on named stack frames. Drop console.* removes console calls as part of compression, a clean way to strip debugging output from a build. The ECMAScript target tells terser which syntax it may emit, so you do not accidentally ship newer syntax than your runtime supports. The combination you choose is saved in your browser for next time.

Sizes, the gzip estimate, beautify and errors

After every run the tool reports the original size, the output size and the percentage saved. Raw bytes, though, are not what a server actually transmits — assets are normally gzip-compressed in transit — so when your browser supports the CompressionStream API the tool gzips the output in memory and shows that figure too; on browsers without it the gzip line is simply omitted rather than invented. Beautify reverses the process: terser prints JavaScript with indentation and comments intact, and a brace-aware pretty-printer re-indents CSS while skipping over strings and comments so it never corrupts a value. When input has a syntax error, csso or terser reports it and the message is shown with its line and column.
