Frequently Asked Questions

Which algorithms are available, and are HMAC and MD5 both supported?

It computes MD5, SHA-1, SHA-256, SHA-384 and SHA-512. SHA-1/256/384/512 use the browser's built-in Web Crypto (crypto.subtle); MD5 is not part of Web Crypto so it uses the SparkMD5 library. HMAC (keyed hashing) is offered for SHA-256, SHA-384 and SHA-512 — enter a secret key and those rows switch to HMAC. There is no HMAC-MD5 or HMAC-SHA1 row because the tool deliberately keeps HMAC on the strong algorithms.

How is text hashed, and what does the 'trim trailing newline' option do?

Text is encoded as UTF-8 with TextEncoder before hashing, so non-ASCII characters (accents, Devanagari, emoji) are hashed as their real UTF-8 bytes — matching what hashlib or sha256sum produce for the same string. Editors and shells often add a newline at the end of a file; the 'Trim one trailing newline' checkbox removes a single trailing \n or \r\n so your result can match a command-line checksum that was taken without it.

Can it hash a 1 GB file without freezing or uploading it?

Yes for MD5 and SHA-256: the file is read in 4 MB slices and hashed incrementally, so it is never fully loaded into memory and a progress bar updates as it goes. Nothing is uploaded — the file is read locally. SHA-1, SHA-384, SHA-512 and file HMAC are computed over the whole file via Web Crypto and are limited to files up to 512 MB, with an on-screen message when a file is larger, because those paths read the entire file into memory.

How does comparing against an expected hash work?

Paste the hash you expect — hex (any case) or Base64 — into the Compare box. It is normalised and checked against every computed digest on the page, so you do not have to pick the algorithm yourself. A green banner names the algorithm that matched; a red banner means it matched none of them. This is the quick way to verify a downloaded file against a vendor's published checksum.

How to Use This Tool

  1. Pick text or file mode. Type into the box for text, or drop a file to checksum a download.
  2. Read the hashes as they appear. Text hashes update live as you type; a file is hashed once with a progress bar.
  3. Choose your output format. Lowercase hex is the usual default; switch to UPPERCASE or Base64 if a system expects it.
  4. Need a keyed hash? Type a secret into the HMAC field and the SHA-256/384/512 rows switch to HMAC.
  5. Verify a download. Paste the vendor's published checksum into "Compare" — a green match or red mismatch tells you instantly.

Common Use Cases

  • Verify an ISO or installer against the SHA-256 the vendor published, before running it.
  • Generate an HMAC-SHA256 signature to test an API or webhook locally.
  • Produce a quick MD5 or SHA-1 fingerprint to spot an accidentally changed file.
  • Compute a SHA-256 of a password or token to compare with a stored digest (for learning/testing).
  • Confirm two files are byte-identical by comparing their checksums.

About This Tool

This Hash Generator computes cryptographic digests of text and files entirely inside your browser. Text is encoded as UTF-8 and hashed with MD5, SHA-1, SHA-256, SHA-384 and SHA-512; files are read on your device and hashed, with large files processed in fixed-size chunks and a progress bar so even a gigabyte-scale file never freezes the tab and never gets uploaded. Hashing Text and Large Files Correctly in the Browser

Why text is hashed as UTF-8, and the trailing-newline trap

A hash is computed over bytes, not characters, so the first question any hashing tool has to answer is how it turns your text into bytes. This tool encodes text as UTF-8 with the browser's TextEncoder before hashing. That matters the moment you type anything outside plain ASCII: the string "नमस्ते" is six Unicode code points but eighteen UTF-8 bytes, and its SHA-256 only matches Python's hashlib.sha256("नमस्ते".encode()).hexdigest() because both sides agree on UTF-8. If a tool silently hashed UTF-16 or Latin-1 instead, your result would disagree with every command-line tool and you would waste an afternoon finding out why.

The second trap is the invisible newline. Text editors and shells habitually append a line feed to the end of a file, so echo abc | sha256sum hashes four bytes, not three, and disagrees with the digest of the literal string "abc". The Trim one trailing newline checkbox removes a single \n or \r\n from the end of your input so you can reproduce a checksum taken either way. Everything you type is hashed live, so the digests update on each keystroke.

How a gigabyte file is hashed without freezing the tab

The Web Crypto API (crypto.subtle.digest) is excellent but has two limits that shape this tool: it has no MD5, and it has no streaming — you hand it one buffer and wait. Loading a 1 GB file as a single buffer to hash it is exactly how a browser tab locks up or runs out of memory. So for the two algorithms whose incremental implementations are verified here, MD5 (via SparkMD5) and SHA-256 (a pure-JavaScript FIPS 180-4 implementation), the file is read in 4 MB slices and fed to the hashing state one slice at a time. Memory stays flat, a progress bar advances, and the event loop yields between slices so the page stays responsive.

SHA-1, SHA-384, SHA-512 and file HMAC are computed with Web Crypto over the whole file, which means they are offered only up to 512 MB. Above that the tool says so plainly rather than pretending; MD5 and SHA-256 still work at any size. This is an honest trade-off: streaming code is shipped only where it has been checked against known answers.

HMAC, output formats, and comparing a hash

Leave the key box empty for plain hashes. Type a secret and the SHA-256/384/512 rows become HMAC, keyed via Web Crypto, which is what you need to sign or verify an API request. Output can be lowercase hex, uppercase hex, or Base64 — different systems publish checksums in different forms, and the Compare box accepts any of them. Paste the hash you expect and it is matched, case-insensitively, against every value on the page, so verifying a download is a glance at a green or red banner.

When not to trust MD5 or SHA-1

Both are marked "not for security" for a reason: practical collision attacks exist, so an attacker can craft two different files with the same MD5 or SHA-1. They remain fine for catching accidental corruption or as cache keys, but for integrity you can rely on, or anything an adversary might attack, use SHA-256 or stronger.
